Product Overview

Product

REVOLVER

Short-term revolving credit for device financing clients and employees. Covers emergency credit requirements with fast 24hr disbursement.

Facility

20%–60% Net Pay

Min 20% / Max 60% of net salary. Tenure of 60 days. Risk-based pricing from 0.25%–0.83% interest. No loan fees or early settlement fees.

Repayment

Mobile Money

Self-repayment via Mpesa, TigoPesa, AirtelMoney. Debit order mandate as additional assurance. Prolongation available at 10% of outstanding balance.

60 days, revolving

Risk Classification

Low Risk (80% of portfolio)
Higher credit assessment scores → lower interest rate. Majority allocation for stable portfolio performance.
High Risk (20% of portfolio)
Lower credit scores → higher interest rate. Limited to 20% of total asset allocation.
CRB Integration
D&B credit bureau check mandatory at onboarding. Defaulters (120+ days) reported to CRB, restricting future credit access.

03 —

WhatsApp Channel Requirements

Technical Requirements

  • WhatsApp Business Platform (Cloud API) — Meta verified Business Account required
  • Webhook server to receive and process inbound messages from WhatsApp
  • Interactive message templates: List Messages (menus), Reply Buttons (confirm/cancel), and Flow messages for multi-step forms
  • 24-hour messaging window handling — use template messages (HSMs) for outbound initiated messages beyond 24hr window
  • Session state management — maintain conversation context per phone number across turns (Redis or similar)
  • Phone number verification against registered client database on every session initiation
  • Language preference stored per client — default Kiswahili, switchable to English within session
  • PIN input handling — masked input, max 5 failed attempts before lockout, server-side validation only
  • Loan amount input validation — numeric only, minimum TZS 5,000, within available facility limit
  • WhatsApp opt-in confirmation required during registration (T&Cs acceptance)
  • Automated notification templates pre-approved by Meta for collection and repayment reminders
  • End-to-end encryption compliance — no storage of message content, only transaction metadata

API Endpoints — Technical Specification

Core Loan Endpoints

POST
/api/v1/loans/apply
Create a new loan request. Validates eligibility, amount limits, account status. Triggers B2C disbursement on approval.
GET
/api/v1/loans/balance/{clientId}
Return current outstanding balance, charges, and available facility for a client.
GET
/api/v1/loans/due-date/{clientId}
Return next repayment due date and amount for the client's active loan.
POST
/api/v1/loans/prolong
Initiate loan prolongation. Validates arrears status (blocked at 90+ days). Extends due date by 30 days on fee payment confirmation.
GET
/api/v1/loans/statement/{clientId}
Return last 5 transactions (DR/CR) for mini statement. Triggers SMS delivery to client mobile number.

Auth, Client & Repayment Endpoints

POST
/api/v1/auth/pin/verify
Validate client PIN. Returns auth token on success. Tracks failed attempts (lock at 5).
PUT
/api/v1/auth/pin/change
Change client PIN. Requires old PIN + new PIN + confirmation. Validates old PIN server-side.
PUT
/api/v1/clients/{clientId}/language
Update client language preference (EN/SW). Applied globally across USSD, WhatsApp, and SMS.
POST
/api/v1/payments/c2b/callback
Webhook for MNO C2B payment notifications. Processes repayments, updates loan balance, triggers confirmation SMS.
POST
/api/v1/ussd/callback
USSD gateway callback handler. Routes menu selections, manages session state, returns appropriate USSD response strings.
POST
/api/v1/whatsapp/webhook
WhatsApp Cloud API inbound webhook. Handles message events, session routing, and interactive message responses.

Back Office — Module Requirements

Module 1
Agent (Registration)

Register clients with employer-provided data. Assign loan limits (20%–60% net pay). Submit to QC. Edit only before QC approval.

Module 2
Quality Control

Verify client data. Run CRB check via D&B API. Approve or decline registration. Manage client suspension/reinstatement.

Module 3
Customer Care

View all clients and batches. Monitor loans, disbursements, repayments, transactions, manual repayments, and bulk adjustments.

Module 4
Finance

All Customer Care views + initiate: adjust repayments (wrong client ID), manual posting, bulk file uploads (principal/interest/penalty adjustments).

Module 5
Administrator

Set loan limits. Configure fees (penalty, prolongation). Manage portal users. Initiate employer creation. Cancel disbursements. View SMS logs & audit logs. Reset client PINs.

Module 6
Authorizer

4-eyes approval layer. Approves: employer creation, product configuration, disbursement cancellations, repayment adjustments, manual postings, bulk file uploads.

⚠ Role Separation Requirements

  • Every sensitive operation (financial adjustments, employer setup, product config) requires an initiator + a separate authorizer — no single user can complete both steps
  • System admin (super-admin) created exclusively by the system developer — not creatable via the portal
  • Complete audit logs for all user actions with timestamp, user ID, IP address, and action detail
  • Agent can only view/edit their own registrations. Customer Care and Finance have read-only access to all client data. Only Admin/Authorizer can modify system configuration.

Automated SMS / WhatsApp Engine Requirements

  • Scheduler job runs daily to identify loans in each collection stage and dispatch messages
  • Messages must be sent in client's stored language preference (EN or SW)
  • All messages must include: amount due, payment reference number, and prolongation fee option where applicable
  • Admin portal must show full SMS log per client with status (sent/failed) and ability to resend
  • WhatsApp notifications use pre-approved HSM (Highly Structured Message) templates registered with Meta
  • De-duplication: do not send duplicate messages if a payment was already received for the day
08 —

Non-Functional Requirements

Performance
  • USSD response time ≤ 2 seconds per interaction
  • WhatsApp message delivery ≤ 3 seconds
  • Loan disbursement via B2C API ≤ 60 seconds end-to-end
  • System must handle concurrent USSD sessions for all registered clients
Security
  • 4-digit PIN with max 5 failed attempts before lockout
  • All API communication over HTTPS/TLS 1.2+
  • PINs stored as bcrypt hashes — never in plaintext
  • WhatsApp webhook signature validation (X-Hub-Signature-256)
  • Role-based access control (RBAC) on all back office modules
  • Full audit logging of all financial operations
Availability & Compliance
  • 99.5% uptime SLA for USSD and WhatsApp channels
  • Compliance with Bank of Tanzania (BoT) regulations
  • CRB integration with licensed D&B bureau only
  • Data residency: all client data stored in Tanzania
  • MNO wallet APIs: Mpesa, TigoPesa, AirtelMoney — all three required
  • Governing law: United Republic of Tanzania

Tech Stack Recommendations

Backend API

  • Node.js / Python (FastAPI or Django) or Java Spring Boot
  • PostgreSQL for transactional data
  • Redis for USSD session state and rate limiting
  • Message queue (RabbitMQ/SQS) for async SMS/disbursement jobs

Integrations

  • WhatsApp Cloud API (Meta for Developers)
  • USSD Gateway (MNO-provided or third-party like Africa's Talking)
  • Mpesa Daraja API (B2C + C2B)
  • TigoPesa & AirtelMoney APIs
  • D&B CRB API (Tanzania)

Back Office Frontend

  • React.js or Vue.js SPA
  • Role-based routing enforced client AND server side
  • Responsive — accessible on tablets and desktop
  • Export: CSV/Excel reports for Finance module
